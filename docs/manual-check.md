# 브라우저 수동 점검 (약 1분)

자동 점검(가짜 DOM + 실제 서버 응답)은 **레이아웃·모바일 폭·포커스 이동·색 대비**를 보지 못한다. 아래를 브라우저에서 한 번 눈으로 확인한다. 서버: `uvicorn prompt2midi.api.app:app --port 8770` (README 참고), 첫 실행 로그의 설정 토큰으로 `/admin` 최초 설정.

| # | 어디서 | 하는 일 | 정상이면 |
|---|---|---|---|
| 1 | `/` (데스크톱 폭) | 페이지를 연다 | 제목·프롬프트 칸·공급자·생성 버튼이 한 열로 가지런하고, 공급자 목록에 "Rule (offline)" 가 보인다 |
| 2 | `/` | 프롬프트에 "밝고 느린 피아노 멜로디" 입력 → 생성 | 결과 카드가 나타나고 사용한 공급자·시드, "MIDI 내려받기" 버튼이 보인다. 키보드 포커스가 결과 카드로 옮겨진다 |
| 3 | `/` | "MIDI 내려받기" 클릭 | `.mid` 파일이 내려받아진다(재생 프로그램에서 열린다) |
| 4 | `/` | "사양(JSON) 보기" 펼치기·접기 | 처음엔 접혀 있고, 펼치면 JSON 이 가로 스크롤 가능한 상자에 보인다 |
| 5 | `/` | 프롬프트 칸을 비운 채 생성 | 빨간 테두리 오류 문구가 보인다(글자 색 대비 충분) |
| 6 | `/` | Tab 키로 처음부터 끝까지 이동 | 건너뛰기 링크 → 프롬프트 → 공급자 → 시드 → 체크박스 → 생성 순, 포커스 표시(주황 윤곽)가 항상 보인다 |
| 7 | `/` 와 `/admin` (창 폭 360px 이하, 또는 개발자 도구 모바일 모드) | 생성까지 해 보고 관리 패널도 훑는다 | 가로 스크롤이 생기지 않고 버튼이 전체 폭이며 글자가 잘리지 않는다 |
| 8 | `/admin` | 로그인 후 패널 | 상단에 노란 "API 키가 암호화되지 않고 저장됩니다" 배너(P2M_SECRET_KEY 없을 때), 공급자 카드 2개, 제한값·공개 설정 카드가 겹침 없이 보인다 |
| 9 | `/admin` | 키 칸에 가짜 키 입력 → 저장 | 입력칸이 비워지고 "키 등록됨 …끝4자" 만 보인다. 새로 고침해도 키 전체는 어디에도 보이지 않는다 |
| 10 | `/admin` | "연결 테스트" 클릭 | 비용 안내 확인 창이 뜨고, 확인하면 "실패/성공 (ms)" 한 줄이 카드 안에 나온다(가짜 키면 인증 실패) |
| 11 | `/` 와 `/admin` | 개발자 도구 콘솔을 연 채로 페이지를 열고 위 항목을 한 번 돌린다 | 'Content Security Policy' 위반 오류가 하나도 없다(인라인 스타일을 모두 없앤 뒤의 확인) |

실패한 항목이 있으면 번호와 브라우저 이름·버전, 화면 폭을 적어 알려 주세요.

## 자동 점검으로 대체되는 항목과 사람 눈이 필요한 항목

CI 의 `browser` job(`tools/browser_check.py`, 헤드리스 **Chromium 하나**)이 위 표의 상당 부분을 단언한다. 로컬에서는 `pip install -r tools/requirements-ci.txt && python -m playwright install chromium && python tools/browser_check.py` (서버는 스크립트가 직접 띄우고 데이터는 임시 디렉터리). 스크린샷(`out/browser/*.png`)과 서버 로그가 Actions 아티팩트 `browser-check` 로 올라간다. 가짜 키는 저장만 하고 외부 LLM 은 호출하지 않는다.

| # | 항목 | 자동으로 대체됨 | 여전히 사람 눈이 필요함 |
|---|---|---|---|
| 1 | `/` 첫 화면 | 제목, 공급자 목록이 "Rule (offline)" 하나뿐(LLM 비노출), 생성 버튼 활성, 글자 색 대비(계산한 CSS 값 기준 WCAG AA) | "한 열로 가지런한가" 같은 배치의 시각적 품질 — 스크린샷 `public-desktop.png` 로 확인 가능 |
| 2 | 생성 → 결과 카드 | 결과 카드 표시, 공급자·시드 문구, 내려받기 버튼 표시, 포커스가 결과 카드로 이동, 글자 수 표시 | 문구가 자연스러운지 |
| 3 | MIDI 내려받기 | 실제 다운로드 이벤트, 파일명 `.mid`, `MThd` 헤더, mido 로 해석되고 이벤트 있음 | **재생해서 들어 보기**(음악적으로 들을 만한지) |
| 4 | 사양(JSON) 접기·펼치기 | 처음 접힘, 펼치면 JSON 표시, 상자가 가로 스크롤 가능(overflow) | 읽기 편한지 |
| 5 | 빈 프롬프트 오류 | 오류 문구와 포커스 이동, 색 대비 계산 | 빨간 테두리가 눈에 띄는지 등 시각 판단 |
| 6 | Tab 이동 | 순서(건너뛰기 → 프롬프트 → 공급자 → 시드 → 체크박스 → 생성), 이동한 모든 요소의 포커스 윤곽(굵기 2px 이상) 존재 | 윤곽이 배경 위에서 충분히 잘 보이는지 |
| 7 | 360px 폭 | `/`·`/admin` 의 가로 스크롤 없음(최초 설정·관리 패널·결과·사양 펼침), `/` 의 생성 버튼이 전체 폭 | 글자가 잘리지 않고 보기 좋은지, **실제 휴대폰 터치** |
| 8 | 관리 패널 배치 | 평문 저장 배너, 공급자 카드 2개, 공개 설정·제한값 카드 존재, `public_llm` 기본 꺼짐 | 카드가 겹치지 않고 보기 좋은지 |
| 9 | 키 저장 | 입력칸 비워짐, 끝 4자 힌트만, 새로 고침 후에도 DOM·브라우저 저장소·설정 API 응답에 키 전체 없음 | — |
| 10 | 연결 테스트 | 비용 안내 확인 창이 뜨는지, 취소하면 요청이 시작되지 않는지 | **확인한 뒤의 "성공/실패 (ms)" 한 줄**은 실제 외부 호출이라 자동화하지 않음(비용 발생). 키를 가진 사람이 직접 확인 |
| 11 | 콘솔·CSP | 콘솔 오류·경고·실패한 요청 0건, `securitypolicyviolation` 0건(`/`·`/admin`, 재로드·360px 구간 포함) | Firefox·Safari 등 **다른 브라우저**(자동 점검은 Chromium 만) |

자동 점검이 일부러 허용하는 것: `/favicon.ico` 요청(응답을 가로채 204 로 대체 — 앱에 파비콘이 없음), `/admin` 점검 중 **일부러 일으킨** 실패 응답(틀린 설정 토큰 403, 재설정 409, 범위 밖 제한값 400, 로그아웃 상태 401) 때문에 브라우저가 남기는 "Failed to load resource" 콘솔 줄. 그 밖의 콘솔 오류는 실패로 센다.

자동 점검이 **하지 못하는 것**(사람 또는 별도 도구): 스크린 리더(NVDA·VoiceOver 등) 읽기 순서와 안내문, 색 대비의 시각적 체감(계산은 하지만 배경 이미지·그라데이션은 없다고 가정), 글꼴 렌더링과 한글 줄바꿈, 다른 브라우저·실제 모바일 기기, 키보드만으로 모든 작업이 끝나는지의 체감, 음악 품질, 실제 LLM 호출(`P2M_LIVE=1` + 관리자가 등록한 키).

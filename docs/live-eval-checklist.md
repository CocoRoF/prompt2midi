# 실제 LLM 평가 체크리스트 (사람이 할 일)

- 도구: `tools/live_eval.py` · 시험: `tests/test_live_eval.py`(가짜 어댑터, 네트워크·비용 0) · 작성: 구본우 · 2026-11-11
- **이 문서의 일은 사람이 한다.** 개발 쪽은 키를 등록하지 않고 비용 상한을 정하지 않는다. 대표님이 키 등록과 비용 상한을 정하기 전에는 실제 호출을 하지 않는다(시험·CI 포함).
- 이 도구가 실제 SDK 호출 경로까지 돌아가 본 적은 **없다**(키가 없어 미확인). 첫 실제 호출이 곧 첫 검증이므로 아래 단계를 작게 시작한다.

## 0. 이 도구가 하는 일 / 하지 않는 일
| 하는 일 | 하지 않는 일 |
|---|---|
| 평가 세트를 단계로 나눠(5 → 20 → 나머지) LLM 공급자로 생성하고 evalkit 과 같은 방식으로 채점해 `results.csv`·`summary.md` 를 쓴다 | 키를 받거나 출력하지 않는다(키는 앱의 키 저장소에서만 읽음, 값은 어디에도 남기지 않음) |
| **기본은 드라이런**: 호출 0, 보낼 요청 수·최대 호출 수만 출력 | 보류(holdout) 세트를 열지 않는다(이름·경로에 `holdout`·`보류`가 있으면 거절) |
| 하루 상한(`daily_llm_cap`)과 `--max-calls` 를 호출 **직전에** 센다. 사용량은 서버와 같은 `usage.json` 에 더한다 | 폴백을 쓰지 않는다(공급자만 측정). 결정성 재생성(호출 2배)도 하지 않는다 |
| 실제 호출 조건이 하나라도 빠지면 호출 0(아래 표) | 음악 품질·분위기를 채점하지 않는다(evalkit 과 같음: "청취 필요") |

실제 호출 조건(전부 필요): ① `--yes-spend` **와** `--max-calls N` ② 환경변수 `P2M_LIVE=1` ③ 관리자 패널에 키·모델 이름 등록 + "사용" 켜짐 ④ 오늘 하루 상한이 남아 있음 ⑤ 앞 단계가 `완료`이고 사람이 `REVIEWED` 를 만들었음. 키가 없으면 `미실행(키 없음)` 으로 끝나며 종료 코드는 0 이다.

## 1. 사람이 결정할 것 (대표님/책임자)
1. **비용 상한**: 이 평가에 쓸 최대 금액.
   - 도구가 통제하는 것은 **호출 수**뿐이다: `--max-calls`(한 번의 실행)와 관리자 패널의 `daily_llm_cap`(하루). 금액은 공급자 **가격표를 사람이 보고** 호출 수로 환산한다(호출 1회 = 입력 시스템 프롬프트+문장, 출력은 사양 JSON, 출력 토큰 한도 기본 4096). 가격은 이 문서에 적지 않는다(미확인, 바뀜).
   - 계산 예: 세트 100개, 재시도 2회 → 최악 300회. 5개 단계의 최악 = 15회.
2. **어떤 세트로 할지**: 개발용 세트(`tests/fixtures/smoke_set.json` 20개는 규칙 공급자 개발용 → LLM 비교에는 부적합) 또는 연구 1팀이 승인한 세트. 세트는 evalkit 형식(`schemas/evalset.v1.schema.json`)이어야 한다.
3. **보류 세트 20개는 쓰지 않는다.** 연구 1팀이 최종 점수를 1회 잴 때만 쓰며, 개발 1팀은 열지 않는다(`docs/eval-metrics.md`). 쓰기로 했다면 사람이 `--holdout` 을 명시한다.
4. **어느 공급자·모델로 할지**: 모델 이름은 코드에 없고 관리자 패널에서 넣는다. 현재 유효한 이름은 공급자 문서로 직접 확인한다(`docs/providers.md` 의 링크).

## 2. 준비 (한 번)
1. 서버를 띄운다: `python -m prompt2midi.api --data-dir <데이터 디렉터리>` (README '서버 실행'). 첫 실행이면 로그의 설정 토큰으로 `/admin` 최초 설정.
   - **`P2M_SECRET_KEY` 를 지정해 키를 암호화해 저장**하길 권한다. 이 평가를 돌릴 때도 같은 값을 환경변수로 줘야 키를 읽는다(없으면 `미실행(키 없음)`).
2. `/admin` 에서 해당 공급자 카드에 **API 키, 모델 이름**을 넣고 **"사용"을 켜서** 저장한다.
3. `/admin` 의 **제한값 → 하루 LLM 호출 상한**을 1번 결정에 맞춰 정한다(이 평가와 서버의 공개 사용이 같은 하루 상한을 나눠 쓴다). 평가 중에는 **`public_llm` 을 꺼 둔다**(기본 꺼짐) — 방문자 요청이 상한과 비용을 쓰지 않게.
4. (선택) "연결 테스트" 버튼은 **비용이 드는 실제 호출 1회**다. 이것으로 키·모델 이름이 맞는지 먼저 본다.
5. 세트 파일 경로를 정한다(보류 세트 아님). 결과는 `out/live-eval/` 아래에 쓰이며 `.gitignore` 의 `out/` 로 커밋되지 않는다.

## 3. 드라이런 (호출 0)
```bash
python tools/live_eval.py <세트.json> --provider anthropic --stage 5 --data-dir <데이터 디렉터리>
```
확인:
- [ ] 세트 이름·개수·sha256 앞 8자가 의도한 세트와 같다.
- [ ] "보낼 요청 최소 N회 · 최대 M회"가 1번 결정의 예산 안이다.
- [ ] "키·설정: 등록됨 · 모델 이름: 설정됨 · 사용 켜짐: 예"(키 값은 출력되지 않는다).
- [ ] "하루 상한 … 남은 호출"이 최대 M회 이상이다.
- [ ] 실제로 `호출하지 않았습니다` 로 끝났다(공급자 콘솔의 사용량이 그대로).

## 4. 단계 5 (첫 실제 호출)
```bash
P2M_LIVE=1 python tools/live_eval.py <세트.json> --provider anthropic --stage 5 --yes-spend --max-calls <최대 15 이하> --data-dir <데이터 디렉터리>
```
`<폴더>` = `out/live-eval/anthropic/stage-5/`. 확인:
- [ ] `manifest.json` 의 `status` 가 `완료`, `llm_calls` 가 드라이런의 최소~최대 범위 안이다.
- [ ] **공급자 콘솔의 실제 요청 수·비용이 `llm_calls` 와 맞는다**(금액을 처음 대조하는 단계. 어긋나면 여기서 멈추고 개발에 알린다).
- [ ] `results.csv` 의 `generated` 가 대부분 `True`. 전부 `False` 면 **멈춘다**: `error` 열을 읽는다(인증 오류 → 키, 모델 없음 → 모델 이름, 거절·잘림 → 프롬프트/토큰 한도). 키 문자열이 보이면 즉시 알리고 키를 교체한다(도구가 가리지만 이중 확인).
- [ ] `retries`·`attempts` 열: 재시도가 몇 번 일어났는지, 어떤 오류로 재시도했는지(`responses.jsonl` 의 `error`).
- [ ] `summary.md` 의 지표가 규칙 공급자 기준선과 비교 가능하다: 같은 `set.json` 을 evalkit 으로 돌려 비교한다.
  `python -m prompt2midi.evalkit out/live-eval/anthropic/stage-5/set.json --provider rule --out out/rule-baseline-5`
- [ ] `responses.jsonl` 의 사양 몇 개를 직접 읽고(곡이 문장과 맞는가), MIDI 를 몇 개 만들어 들어 본다(자동 채점이 못 보는 부분).
- [ ] 이상이 없으면 확인했다고 표시한다: `touch out/live-eval/anthropic/stage-5/REVIEWED`

## 5. 단계 20 (다음 15개: 6~20번째)
단계 5 와 같은 명령에서 `--stage 20` 만 바꾼다(`--max-calls` 는 최대 45 이하 권장). 단계 5 가 `완료`이고 `REVIEWED` 가 없으면 도구가 거절한다. 확인 항목은 4절과 같고 추가로:
- [ ] 단계 5 와 비교해 생성 성공률·재시도 횟수가 비슷하다(급변하면 원인을 먼저 찾는다).
- [ ] 누적 비용이 1번 결정의 상한의 절반 이하다(전체 단계 예상이 상한을 넘을 것 같으면 여기서 멈추고 다시 결정).
- [ ] `touch out/live-eval/anthropic/stage-20/REVIEWED`

## 6. 전체 (21번째부터 끝까지) 와 마무리
`--stage all`. 확인 항목은 4절과 같고 추가로:
- [ ] `manifest.json` 이 `완료`(`중단(...)`이면 상한에 닿아 일부만 처리된 것 — 상한을 다시 정하고 같은 단계를 `--rerun` 으로 돌리면 **그 단계를 처음부터** 다시 호출한다는 점을 알고 결정).
- [ ] 세 단계의 `results.csv` 는 겹치지 않는 구간이다. 합치려면 같은 머리글이므로 첫 파일 외의 머리줄을 빼고 이어 붙인다. (합친 요약 `summary.md` 는 이 도구가 만들지 않는다 — 필요하면 합친 `set.json` 으로 evalkit 쪽 확장을 요청.)
- [ ] 결과(`results.csv`, `summary.md`, `manifest.json`)를 연구 1팀에 전달한다. **`responses.jsonl`·`set.json` 도 함께**(같은 세트를 evalkit 규칙 공급자로 돌린 기준선과 비교).
- [ ] 평가가 끝나면 필요 없는 키는 `/admin` 에서 삭제하거나 "사용"을 끈다.

## 7. 문제가 생기면
| 증상 | 의미·조치 |
|---|---|
| `미실행(키 없음)` | 키 저장소에 키가 없거나 암호화 키(`P2M_SECRET_KEY`)가 달라 못 읽음. `--data-dir`·환경변수 확인 |
| `미실행(모델 미설정)`·`(사용 꺼짐)` | `/admin` 에서 모델 이름을 넣고 "사용"을 켠다 |
| `미실행(P2M_LIVE=1 아님)` | 의도한 호출이면 환경변수를 준다 |
| `미실행(하루 상한 소진)` | 내일(UTC 기준 날짜) 또는 사람이 `daily_llm_cap` 을 올리기로 결정 |
| `중단(--max-calls 에 닿음)` / `(하루 상한 … 에 닿음)` | 의도한 정지. 그 항목부터는 호출하지 않았다 |
| `단계 진행 불가: …` | 앞 단계 미완료·미확인(REVIEWED)·다른 세트. 메시지의 안내대로 |
| 종료 코드 1 + "결과 파일에 키 문자열이 섞여 모두 지웠습니다" | 도구 방어선이 작동한 것. 키를 교체하고 개발에 알린다 |

## 8. 확인하지 못한 것 (이 도구의 한계)
- 실제 Anthropic·OpenAI SDK 호출 경로는 키가 없어 한 번도 돌려 보지 못했다(시험은 가짜 어댑터).
- 호출당 비용(토큰 수·단가)은 추정하지 않았다. 단계 5 에서 공급자 콘솔과 대조해 정한다.
- `usage.json` 은 파일 단위로 쓰며 서버와 이 도구가 **동시에** 같은 날 호출하면 사용량이 한두 건 어긋날 수 있다(그래서 평가 중 `public_llm` 을 끈다).
- 합친 요약과 세 단계의 통합 CSV 는 만들지 않는다.

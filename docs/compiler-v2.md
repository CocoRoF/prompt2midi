## 0. 요약과 결정이 필요한 쟁점

- v2 는 **옵트인**이다. `MusicSpec` 에 선택 필드 `engine` 하나를 더하고, 없거나 `"v1"` 이면 지금 동작과 **바이트 동일**하다. `version` 은 `"1"` 로 둔다.
- 함정 하나를 이미 찾았다 (**확인**): `canonical_json()` 은 `None` 필드도 직렬화한다. 새 선택 필드를 그냥 더하면 모든 기존 사양의 내용 해시(=seed 가 없을 때의 seed)가 바뀌어 v1 출력이 통째로 달라진다. PR1(#33)에서 `engine` 을 해시 입력에서 항상 빼도록 고쳤고, 120건 고정 해시로 막는다 (§3.3).
- 구현은 PR 5개로 쪼갠다 (§7). PR1 은 동작을 바꾸지 않는 기반(필드·측정 도구·기준선)이고, 음악이 달라지는 것은 PR2 부터다.

결정이 필요한 쟁점은 §9 에 모았다.

## 1. 현재(v1) 동작 — 읽어서 확인한 것

`src/prompt2midi/compiler/render.py`, `drums.py`, `rng.py`, `spec.py`, `music.py` 기준.

### 1.1 공통
- SMF format 1, 480 PPQ, 역할당 트랙 하나. 채널: 선율 0 · 베이스 1 · 화음 2 · 패드 3 · 드럼 9.
- RNG: 자체 mulberry32 `Rng(seed, label)` (label 은 FNV-1a 로 섞음). 역할마다 따로 만들어서 한 역할의 호출 횟수가 다른 역할에 번지지 않는다. 기본 seed = `effective_seed(spec)` = `spec.seed`, 없으면 `canonical_json` 의 sha256 앞 4바이트.
- 시간 뼈대: 섹션 → 마디 → 화음 칸(`_slots`). 한 칸 = 화음 하나와 그 길이.

### 1.2 선율 `_melody_track`
섹션마다 `shift = rng.choice([0, 0, 1, -1, 2])` 를 한 번 뽑는다. `motif_pitches(spec, track, shift)` 가 모티프 음도를 `shift` 만큼 음도 이동해 음높이 목록을 만들고(음역을 넘으면 `shift=0` 으로 되돌림), 섹션 끝까지 **리듬 목록을 순환**하면서 음높이 목록도 **순환**한다 (`ni`, `ri` 가 따로 돈다). 쉼표 기호는 시간만 쓴다. 음 길이는 `0.92` 배, 벨로시티는 `_vel(65, energy, rng)`.

한계 (구조상 그렇다 — 청취 평가가 아니라 코드에서 나온 사실):
- 섹션 안은 **같은 모티프의 단순 반복**이다. 발전(시퀀스·변형)도, 제시→종지의 모양도 없다.
- 음높이가 **화음과 무관**하다. 코드톤 여부를 보지 않는다. 화음이 바뀌어도 선율은 모른다.
- 리듬 길이와 음높이 길이가 서로소가 아니면 같은 조합이 계속 겹치고, 서로소면 박마다 다른 음이 붙는다 — 어느 쪽이든 의도한 것이 아니다.
- 프레이즈 호흡 없음(모티프에 쉼표가 있을 때만). 마지막 마디도 그냥 섹션 끝에서 **자른다** (`min(length, sec_end - t)`).
- 이동은 섹션마다 한 번, 5개 중 하나. 윤곽·음역 제어는 `motif_pitches` 의 "음역 안에 들어가는가"뿐.

### 1.3 베이스 `_bass_track`
화음 칸마다 근음을 음역 `lo..hi` 안의 가장 낮은 옥타브에 둔다. `energy < 0.5` 면 칸 전체에 근음 한 개. 그 이상이면 **박마다 한 음**: `k % 4 == 2` 인 박에서 60% 확률로 5도(`root+7`, 음역을 넘으면 근음), 나머지는 근음. 선율·화음과 상호작용 없음. 화음 사이를 잇는 경과음도 없음.

### 1.4 화음·패드 `_chords_track` / `_chord_pitches`
화음의 각 구성음(`CHORD_TONES[quality]`)에 대해 음역 안에서 `center` 에 가장 가까운 같은 음이름 음을 고르고 정렬한다. `center` 는 처음에 음역의 가운데, 이후에는 **직전 보이싱의 평균음높이**다. 즉 "평균 가까이"라는 약한 형태의 보이스 리딩은 이미 있지만, 개별 성부를 이어 주는 것이 아니고 **전위(가장 낮은 음이 3음/5음)를 의도적으로 고르지도 않는다.** `pad` 이거나 `energy < 0.35` 면 칸 전체를 지속음, 아니면 박마다 짧게 친다 (`CHORD_PATTERN`).

### 1.5 드럼 `drums.py`
8분음표 격자(`GRID[박자표]`)와 스타일별 `bar_hits` (rock_basic · four_on_floor · half_time · shuffle · bossa …). 셔플 오프셋, 하이햇 솎기, 섹션 끝 스네어 필인은 `render.py` 에서 처리. **v2 에서 드럼은 건드리지 않는다** (§8).

### 1.6 사양 쪽
`MusicSpec` 은 닫혀 있다(`extra="forbid"`, `version: Literal["1"]`). 화음 진행은 `Section.chords`(화음 이름 목록). 섹션에는 `bars`, `energy` 가 있고, 트랙에는 `motif`(음도·리듬)와 `register`(별칭, 필드명 `pitch_range`)가 있다. 모티프는 트랙당 하나뿐이다.

### 1.7 v1 대리 지표 기준선 (직접 돌린 값)
`RuleProvider` 로 만든 사양을 컴파일해서 MIDI 에서 잰 값이다. 측정 스크립트는 이번 PR 에 넣지 않았고, PR1 에서 `tools/` 에 정식으로 넣는다 (그때까지의 값은 임시 스크립트 결과이므로 PR1 에서 재현해 확정한다).

| 강박의 코드톤 비율 | 0.49 | 0.46 |
| 서로 다른 음높이 수 | 7.2 | 6.8 |

## 3. 호환성 결정

### 3.1 결정: 옵트인 필드 `engine`
`MusicSpec.engine: Literal["v1", "v2"] | None = None`. `None`·`"v1"` → 현재 코드 경로 그대로. `"v2"` → 새 경로.

이유:
1. 해시로 고정한 시험(`tests/fixtures/legacy_unchanged.json` 120건, `tests/test_compiler.py` GOLDEN, `data/eval_rule_results.csv`, `tests/test_rule_intent_path.py` 의 연구 문구 해시)이 v1 바이트 동일을 전제한다. 기본 동작을 바꾸면 이 시험들을 전부 다시 쓰게 되고, **무엇이 의도한 변화이고 무엇이 회귀인지 구별할 수 없게 된다.**
2. 같은 사양에 `engine` 만 바꿔 v1/v2 를 컴파일할 수 있으면 **전후 비교가 쌍으로 가능**하다 (같은 프롬프트·같은 seed·같은 화음 진행).
3. 청취 평가 전에 기본값을 바꾸지 않는다. v2 가 낫다는 근거가 모이면 별도 결정으로 기본을 바꾼다.

### 3.2 `version` 필드는 올리지 않는다
`version` 은 `"1"` 로 둔다. 필드를 **더하기만** 하므로 사양 구조는 하위 호환이다(옛 사양 파일은 그대로 통과). "버전 없음 = v1 동작" 규칙은 `engine` 에 그대로 적용된다. `version: "2"` 는 v2 를 **기본값**으로 바꾸는 날을 위해 남겨 둔다. 단, **옛 코드는 `engine` 이 든 사양을 거부한다**(`extra="forbid"`) — 이것은 알려진 비대칭이며, 새 사양을 옛 버전에 넘기지 않는다는 전제다.

### 3.3 내용 해시 함정 (**확인**) 과 처리
`canonical_json()` 은 `spec.model_dump(...)` 를 `None` 포함으로 직렬화한다. `engine=None` 이 `"engine":null` 로 들어가면 **seed 가 없는 모든 기존 사양의 seed 가 바뀐다.** 처리:
- **구현된 결정 (PR #33, 권나경 승인):** `engine` 은 값과 상관없이(`None`·`"v1"`·`"v2"`) **항상** 해시 입력에서 뺀다 (`spec.HASH_EXCLUDED_FIELDS = {"seed", "engine"}`). 이전 초안은 `"v2"` 일 때만 해시에 넣어 v2 의 seed 가 v1 과 달라지게 했으나, seed 가 없는 사양에서 "v2(위임)=v1 바이트 동일"이 성립하지 않고 같은 사양의 v1/v2 쌍을 같은 seed 로 비교할 수 없어 바꿨다.
- v2 가 v1 과 같은 seed 로 시작해도 난수열은 겹치지 않는다: v2 는 단계별로 다른 `Rng` 라벨(`melody.section`·`melody.develop`·`melody.vary`·`melody.vel` …)을 쓴다 (§3.4).
- 앞으로 더하는 옵트인 필드도 같은 원칙으로 `HASH_EXCLUDED_FIELDS` 에 넣는다(새 필드가 `None` 일 때 기존 사양의 seed 가 변하지 않아야 한다).
- 고정 시험: 위 120건·GOLDEN·CSV 해시가 그대로 통과해야 PR1 이 병합 가능.
- `schemas/musicspec.v1.schema.json` 은 생성물이므로 PR1 에서 재생성한다(필드 추가분만 차이).

### 3.4 결정론 (요구 ①)
- v2 도 자체 `Rng` 만 쓴다. `random`·`numpy`·시간·해시 순서에 의존하지 않는다. 사전/집합 순회는 정렬해서 쓴다.
- v2 는 역할·단계별로 **라벨이 다른 `Rng`** 를 쓴다 (예: `melody.develop`, `melody.cadence`, `harmony.variation`). 한 단계에서 호출 횟수가 바뀌어도 다른 단계의 난수열이 밀리지 않는다.
- 시험: 같은 사양 두 번 컴파일 → 바이트 동일; 3.12/3.14 두 파이썬에서 동일 해시 (기존 uv 매트릭스).

## 4. 선율 v2 (우선순위 1)

모든 규칙은 사양에 이미 있는 값(조성·화음·모티프·음역·에너지·마디 수)만으로 계산한다. 새 사양 필드는 필요하지 않다 (§4.7 의 선택 노브 제외).

### 4.1 프레이즈 구조: 제시 – 발전 – 종지
섹션을 **프레이즈**로 자른다. 기본 프레이즈 길이 = 4마디(섹션이 4의 배수가 아니면 마지막 프레이즈가 2~3마디; 1마디 섹션은 종지만). 섹션 안의 프레이즈 역할:

| 프레이즈 위치 | 역할 | 처리 |
|---|---|---|
| 첫 프레이즈 | 제시 | 모티프를 변형 없이(음도 이동 0) 제시. 끝 마디만 §4.5 종지 |
| 중간 프레이즈 | 발전 | §4.2 의 연산을 번갈아 적용 |
| 마지막 프레이즈 | 종지 | 앞 프레이즈의 앞 2마디를 재사용하고 뒤 마디를 종지로 교체 (질문–대답) |

섹션 하나가 한 프레이즈(4마디 이하)이면 1~2마디째 제시, 나머지 발전·종지. 비교: v1 은 이동 한 번에 같은 모양을 끝까지 반복한다.

### 4.2 발전 연산 (모티프 → 변형)
모티프는 (음도 목록, 리듬 목록)이다. 연산은 모두 이 둘에 대한 순수 함수다.
- **반복**: 그대로 (제시 직후의 두 번째 마디 군).
- **시퀀스**: 음도를 `+1`/`−1`/`+2` 이동(조성 안의 음도 단위)해서 한 번 더. 이동량은 라벨 RNG 로 후보 `[+1, −1, +2]` 에서 뽑되, 같은 방향 시퀀스는 연속 2회까지.
- **변형**: (a) 리듬 보존 · 마지막 음만 바꿈, (b) 윤곽 반전(음도 간격의 부호를 뒤집음), (c) 리듬 축약(마지막 음 두 개를 하나로 합침) 중 하나. 변형은 프레이즈당 한 번 이하.
- 연산 선택은 규칙 기반 순환(제시→반복→시퀀스→변형)에 RNG 는 **후보 중 선택**에만 쓴다. 동일 연산을 3프레이즈 연속 쓰지 않는다.

### 4.3 코드톤 + 경과음 규칙
발전 연산으로 나온 음도에 대해 **보정** 단계를 거친다:
1. 화음 칸이 시작하는 박과 강박(`GRID` 의 kick 위치)에 놓인 음은 **코드톤이어야 한다.** 아니면 가장 가까운 코드톤으로 옮긴다(같은 거리면 직전 음에서 더 가까운 쪽, 그래도 같으면 위쪽).
2. 약박의 음은 비화성음을 허용하되 **경과음(순차 진행으로 코드톤 사이를 잇는 것) 또는 이웃음(코드톤으로 돌아오는 것)** 일 때만 허용한다. 두 조건 중 어느 쪽도 아니면 가장 가까운 코드톤으로 옮긴다.
3. 조성 밖 음은 만들지 않는다 (경과음도 조성의 음계음만). 장르별 크로매틱은 이번 범위 밖.
4. 보정은 음높이만 바꾸고 리듬은 바꾸지 않는다.

기대: 강박 코드톤 비율이 1.0 에 가까워진다(규칙으로 강제하므로 지표는 당연히 오른다 — 그것은 **규칙이 구현됐다는 증거일 뿐 음악이 좋아졌다는 증거가 아니다**).

### 4.4 음역·윤곽 제어
- 프레이즈의 **정점**(가장 높은 음)을 프레이즈당 하나로 한정한다. 정점은 프레이즈 2/3 지점에 오도록 시퀀스 이동량을 클램프한다.
- 도약 제한: 5반음 이상 도약(완전4도 초과) 뒤에는 **반대 방향의 순차 진행**. 옥타브 초과 도약 금지.
- 에너지 연동: 섹션 `energy` 가 높을수록 프레이즈 음역의 중심을 올린다(음역 안에서 `lo + (hi-lo)*(0.35+0.4*energy)`). 낮으면 내린다.
- 음역을 벗어나는 음은 옥타브 이동으로 접어 넣는다(음이름 유지).

### 4.5 종지와 마지막 마디
- 프레이즈 끝(마지막 한 마디): 마지막 화음의 코드톤으로 끝나며 **직전 음은 순차 진행으로 접근** (이끎음/2도).
- 섹션 마지막 프레이즈의 끝 = **완결 종지**: 마지막 음은 마지막 화음의 근음 또는 3음(근음 우선), 길이는 **마디 끝까지 늘리되 마지막 마디의 남은 박 전부**(v1 의 자르기를 대체).
- 곡 전체의 마지막 마디는 한 음(또는 모티프 마지막 리듬을 늘린 형태)으로 마치고 **여운**을 위해 음 길이 0.92 배 대신 마디 끝까지 유지한다 (§5.4 화음 쪽 종지와 맞춘다).
- 중간 섹션 끝은 **반종지**를 허용: 마지막 음이 5음 또는 화음의 다른 코드톤(미완결 느낌). 어느 쪽을 쓸지는 섹션 이름·순서에서 결정하지 않고 "마지막 섹션이 아니면 반종지, 마지막이면 완결"로 단순하게 한다.

### 4.6 프레이즈 호흡(쉼표)
- 프레이즈 끝에서 **마지막 음을 최소 0.5박 짧게** 하고 숨 쉼을 둔다(종지 음 제외: 완결 종지는 쉼 없이 지속).
- 4마디 프레이즈의 3마디째 끝에도 짧은 쉼 가능(에너지 낮을 때만).
- 쉼은 시간을 늘리지 않고 앞 음의 길이를 줄이는 방식 → 박 구조·마디 길이 불변.
- 청취 없이 정할 수 없는 값(쉼의 길이)은 상수 하나로 노출하고 **미확인**으로 둔다.

### 4.7 선택 노브 (필요한 경우에만, PR2~3 중 결정)
`Track.melody_style` 같은 필드를 미리 만들지 않는다. 먼저 규칙을 고정하고, 청취 후 필요가 확인되면 §9 쟁점으로 올린다.

### 4.8 `engine="v2"` 의 모티프 처리
모티프가 비어 있는 사양은 이미 검증에서 걸러진다(기존 검증 유지). 모티프가 너무 짧아(음 1개) 시퀀스/변형이 의미 없을 때는 시퀀스만 적용하고 변형은 건너뛴다.

## 5. 화성 v2 (우선순위 2)

### 5.1 보이스 리딩 (최소 이동)
현재 `_chord_pitches` 는 평균 높이에 가까운 음을 고를 뿐이다. v2 는 직전 보이싱 → 다음 화음의 **성부 대응**을 푼다:
- 후보: 다음 화음의 모든 전위(각 구성음을 음역 안에서 가능한 옥타브에 두는 조합).
- 비용 = 성부별 이동 절대값의 합 (+ 음역 이탈 큰 벌점 + 성부 교차 벌점). 가장 작은 비용의 후보를 고른다. 비용이 같으면 낮은 쪽 후보 우선(결정적).
- **공통음 유지**: 두 화음의 공통 음은 같은 높이로 둔다(비용이 자연히 0).
- 평행 5도/8도 같은 고전 금지 규칙은 이번엔 넣지 않는다 (팝/재즈 보이싱 대상이고 규칙이 오히려 어색할 수 있음 — **미확인**, §9).

### 5.2 전위
- 베이스 트랙과 화음 트랙이 **함께** 있으면: 화음 트랙은 항상 구성음 전체를 가지고, 전위는 보이스 리딩의 결과로만 생긴다(전위를 따로 고르지 않음).
- 베이스가 근음 대신 **3음/5음**을 연주하는 슬래시 코드는 §5.3 의 연결음에서만 쓴다(전체에 쓰지 않음).

### 5.3 베이스 v2 (화성 쪽에 묶음)
- 칸 전체 근음 + (에너지 높을 때) 박 단위 패턴은 유지하되, **칸 마지막 박**에서 다음 화음 근음으로 **경과음/접근음**(다음 근음의 반음/온음 아래 또는 위)을 허용 (에너지 ≥ 0.5, 다음 칸이 있을 때).
- 5도 삽입 확률은 규칙화: 3박 이후만, 같은 칸에서 2회까지.

### 5.4 섹션별 코드 변주와 종지 패턴
화음 진행(`Section.chords`)은 사양이 정한다. v2 는 사양의 화음을 **바꾸지 않고**, 컴파일 시 **연주용 화음**을 만든다 (사양 파일은 그대로, MIDI 만 달라짐):
- **대체 코드**(옵트인 엔진 안에서만): 장조 `I` → `vi`(약한 변형), `IV` → `ii`, `V` → `V7` 등 **같은 기능(토닉/서브도미넌트/도미넌트)** 의 코드로만 교체. 섹션 반복 회차가 늘수록(같은 화음 진행을 다시 쓰는 두 번째 섹션부터) 교체 확률을 올린다. 마지막 섹션·마지막 마디는 교체하지 않는다.
- **종지 패턴**: 섹션의 마지막 두 화음이 `... → V → I`(진정 종지)이면 `V` 를 `V7` 로, 반종지 섹션이면 `V` 에서 끝. 사양의 마지막 화음이 이미 토닉이면 그대로.
- 교체 후에도 모든 코드톤은 **조성 음계음 또는 허용 크로매틱**(`V7` 의 7음 등 `check_theory` 가 이미 허용하는 범위)이어야 한다. 지금 `check_theory` 가 막는 화음은 만들지 않는다.
- 장르 사양이 블루스/재즈로 이미 7th 를 쓰고 있으면 교체를 건너뛴다(평가 지표의 25% 규칙과 어긋나지 않게 — evalkit v0.4 기준).

### 5.5 화음 패턴
박마다 치는 패턴(`CHORD_PATTERN`)과 지속음 판단(`energy`, `pad`)은 유지한다. 바뀌는 것은 보이싱(음높이)뿐 → 리듬/벨로시티 변화는 PR 범위 밖.

## 6. 음악 이론 규칙만 쓴다 (요구 ③)
외부 악보·MIDI·코퍼스·학습 모델·라이선스 불확실한 패턴 목록을 쓰지 않는다. 쓰는 것: 음계/코드톤 정의(코드에 이미 있음), 경과음·이웃음·시퀀스·종지 같은 일반 이론 개념, 직접 쓴 상수. 코드 안에 모티프 라이브러리를 새로 넣지 않는다(모티프는 사양이 준다). 이 문서의 규칙 출처는 일반 화성학/작곡 입문의 통념이며 특정 저작물을 옮기지 않았다.

## 7. 구현 순서 — PR 별 계획

공통: 각 PR 은 시험이 통과해야 하고 v1 고정 해시 시험(120건·GOLDEN·CSV·연구 문구)이 변하지 않아야 한다. 각 PR 은 작게, 명시 경로로 add, 3.12/3.14 매트릭스.

> **지표를 읽는 법.** 아래 "기대 변화"는 규칙을 구현했다면 그렇게 나와야 하는 **대리 지표**의 방향이다. 지표가 오른 것은 규칙이 작동한다는 증거이지 **음악이 좋아졌다는 증거가 아니다.** 반대로 지표가 같아도 듣기에 다를 수 있다. 음악 품질은 청취로만 판단할 수 있고 그 평가는 **미확인**이다 (§10).

## 9. 결정이 필요한 쟁점 (권나경)
1. **`engine` 필드 방식**(권장) vs `version: "2"`. 권장 이유는 §3. `version` 을 올리면 옛 사양이 여전히 읽혀야 하므로 결국 "없음 = v1" 규칙이 또 필요하다.
2. **`canonical_json` 의 None-제외 변경**을 PR1 에 포함해도 되는지. v1 출력은 바뀌지 않지만 해시 함수 수정이라 검토가 필요하다.
3. **고전 보이스 리딩 금지 규칙(평행 5·8도)** 을 이번에 넣을지(기본: 넣지 않음).
4. **반종지 단순 규칙**("마지막 섹션이 아니면 반종지")으로 시작해도 되는지, 섹션 이름(`chorus` 등)을 쓸지.
5. **PR 크기/순서**: PR2~3 을 합칠지 (선율을 한 번에 보려면 합치는 편이 청취 비교에 편하다. 나눌 때의 장점은 리뷰 크기).
6. 청취 평가를 **누가 어떻게** 할지 (기준표, 쌍 비교 방식). 나는 판단할 수 없다.

## 11. 구현 메모 (PR2·PR3 에서 설계서와 달라진 점)

- **음도 단위 처리(PR2):** 선율은 음계 위 단계(scale-step) 번호로 다루고, 코드톤 보정만 음계 밖으로 나갈 수 있다. 모티프가 음역에 안 들어가는 사양은 v1 선율로 되돌린다.
- **코드톤 스냅(PR3 에서 손봄):** PR2 의 "가장 가까운 코드톤"은 도약(0.13→0.245)과 반복음(0.03→0.22)을 만들고 모티프 윤곽을 깎았다(음정 부호 일치 0.80 → PR3 초안 0.62). 스냅 비용에 ① 직전 음과의 도약(4반음 넘는 만큼 가중 2) ② 모티프 방향과 반대로 가는 것(6반음 상당)을 더해 방향을 지키게 했다. 상수는 `melody_v2.py` 머리의 `LEAP_COST_*`·`CONTOUR_COST`.
- **정점(§4.4):** "정점을 시퀀스 이동량으로 2/3 지점에 오게 클램프"는 하지 않았다. 대신 프레이즈 안에서 같은 최고 높이를 가진 음 중 2/3 지점에 가까운 하나(종지 음이면 그것)만 남기고 나머지는 한 단계 낮은 코드톤으로 내린다. **변형 없는 제시·반복(`orig`) 패스의 음은 건드리지 않는다**: 모티프가 매 패스마다 같은 최고음을 갖는 것이 정상이고, 전부 내리면 모티프 보존율이 0.80 에서 0.72 로 떨어졌다(측정).
- **도약 규칙(PR3 수정 반영):** 옥타브 초과 도약은 막는다(옥타브 이동). 5반음 이상 도약에 대해 세 가지를 시도한다: (A) 도약 뒤 다음 음이 **강박이어도** 코드톤 중 반대 방향·더 작은 이동의 것으로 바꾼다. (B) 약박·비제시 음으로 들어가는 도약은 5반음 안쪽의 코드톤으로 줄인다. (C) 약박 비화성음으로 **이탈음(escape tone: 순차로 벗어났다가 반대쪽 코드톤으로 도약)** 을 추가로 허용한다 — 설계서 §4.3 의 "경과음·이웃음만" 에 하나 더한 것이며 일반 화성학의 비화성음 유형이다. 강박 음은 여전히 코드톤이 우선이다.
  측정(baseline-v0 16곡, v1 → 시도 전 → A·B·C 전부): M2 `recovery` 0.717 → 0.262 → **0.378**, 도약 0.130 → 0.195 → **0.182**, 순차 0.372 → 0.273 → **0.303**, 모티프 보존율 0.796 → **0.770**. 항목별(시도 전 대비 recovery / 보존율): A 0.315 / 0.780, B 0.276 / 0.805, C 0.328 / 0.776 — 셋을 합치면 가장 좋았고 보존율은 0.03 내려간다(A·B·C 개별 값은 이 구현 직전 측정이라 최종 수정(강박 위 비화성음 금지)과 소수점 이하가 다를 수 있다).
  **한계(개선 안 된 것):** `recovery` 는 v1(0.717)에 못 미친다. v1 은 모티프의 순차 진행이 그대로 남지만 v2 는 강박을 코드톤으로 바꾸므로, 도약 뒤 "반대 방향 2반음 이내"가 코드톤 사이에서는 잘 나오지 않는다. **반복음 비율(0.134)은 v1(0.027)의 5배로 남았다** — 스냅 비용에 반복음 벌점을 더해 봤으나(0·3·6) 0.132→0.127 로 거의 변화가 없어 넣지 않았다(원인은 코드톤 스냅이 아닐 수 있으나 미확인). 이 값들은 임시 범위의 대리 지표이고 청취는 미확인이다.
- **종지(PR3 수정 반영):** 곡의 마지막 음(완결 종지)은 마지막 화음의 구성음에서 고르되 선택 순서는 ① 조의 으뜸음(tonic pc)이 구성음이면 그것 ② 조의 삼화음의 3음, 5음 순으로 구성음인 것 ③ 없으면 화음 근음. 예(C 장조): IV(F A C)→C, vi(Am)→C, V(G B D)→G(5음), iii(Em)→E(3음), ii(Dm)→D(근음). 시험으로 순서를 고정했다. 반종지(마지막이 아닌 섹션)는 5음(없으면 3음·그 밖의 구성음). 프레이즈 끝은 코드톤, 직전 음은 2도 이내 접근을 시도. 곡 마지막 음은 마지막 마디 끝까지 지속한다. baseline-v0 16곡 중 마지막 화음의 근음이 으뜸음인 곡은 0곡(직접 확인)이라 이전 초안(근음)에서는 으뜸음 도착이 0 이었고, 위 순서로 M4 `final_is_tonic` 이 0.5, `final_score` 가 v1 0.219 → **0.531** 이 되었다. **으뜸화음으로 닫는 종지는 여전히 화성 쪽(§5.4, PR5)의 몫**이다: 지금은 IV 위의 으뜸음처럼 화음 위에서 어색할 수 있는 마무리도 만든다(청취 미확인).
- **호흡:** 프레이즈 끝(완결 종지 제외)과, 에너지 0.5 미만 4마디 이상 프레이즈의 3마디째 끝에 0.5박 쉼. 쉼의 길이 등 **청취로만 정할 수 있는 상수(미확인)** 는 `melody_v2.py` 머리 한 곳(`BREATH_BEATS`, `MIN_NOTE_BEATS`, `APEX_POSITION`, `CENTER_*`, `BREATH_ENERGY_MAX`)에 모았다.
- **에너지 연동 음역:** 섹션을 음역 중심(`lo+(hi-lo)*(0.35+0.4·energy)`) 쪽으로 최대 2음도 옮긴다. 계수는 미확인.

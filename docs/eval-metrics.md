- 구현: `src/prompt2midi/evalkit/` · 실행: `python -m prompt2midi.evalkit <세트.json> --provider rule|fake [--out DIR] [--fallback]`

## 1. 평가 세트 형식 (version "1")

JSON Schema: `schemas/evalset.v1.schema.json` (코드의 모델에서 생성, 시험이 일치를 확인). 형식:

```json
{"version": "1", "name": "세트 이름",
 "prompts": [
  {"id": "a01", "lang": "ko|en", "tier": "A|B|C", "text": "프롬프트 문장",
   "expect": {"tonic": "C", "mode": "major", "tempo_bpm": 70, "time_signature": "4/4", "bars": 12, "instruments": ["piano", "drums"]}}
 ]}
```
- `id`: 세트 안에서 유일(`[A-Za-z0-9_.-]`, 64자 이하). `lang`·`tier`는 필수. 층(A/B/C)의 뜻은 세트 작성자(연구 1팀)가 정한다 — 하네스는 집계 단위로만 쓴다.
- `expect`(정답 라벨)는 **프롬프트에 글자로 적힌 속성만** 넣는다. 전부 선택이다. 라벨이 없는 항목은 그 지표가 **`na`(해당 없음)** 가 되어 분모에서 빠진다. 무드·장르·음악성은 라벨 필드가 없다(자동 채점 대상이 아님).
- `tonic`은 사양의 `Tonic` 값(이명동음 `C#`/`Db`는 같은 음으로 비교), `mode`는 `Mode` 값, `instruments`는 사양의 `Instrument` 값 + `drums`.
- 알 수 없는 필드, 범위 밖 값, 중복 id, 빈 세트는 **거부**한다(종료 코드 2, 문제 목록 출력).
- **보류 세트**: 개발 1팀은 보류분을 열지 않는다(합의안 8절). 하네스는 세트 **파일 경로를 인자로 받을 뿐**이며 보류 파일을 레포에 두지 않는다. `.gitignore` 에 `data/eval/holdout*` 가 들어 있어 실수로 올라가는 것을 막는다. 최종 점수는 1회만 잰다(연구 1팀 규칙).

## 2. 지표 (pass / fail / na)

모든 지표는 `pass`, `fail`, `na` 와 사유 문자열을 낸다. **집계의 분모 = pass + fail.** `na` 는 분모에서 빼고 따로 개수만 적는다. 생성 자체가 실패한 프롬프트는 라벨이 있는 지표와 유효성 지표에서 `fail`(사유 "생성 실패")이다 — 시스템이 요구를 못 채운 것이므로 분모에 남긴다. 라벨이 없으면 생성이 실패해도 `na`.

| 지표 (코드 이름) | 무엇을 보나 | 합격 판정 | 해당 없음(na) | 한계 |
|---|---|---|---|---|
| 템포 일치 `tempo_match` | MIDI 첫 `set_tempo` 의 BPM 과 `expect.tempo_bpm` | 차이 ≤ 0.5 BPM | 라벨 없음 | 곡 중간 템포 변화는 보지 않음. 라벨은 정수 BPM |
| 조성 일치 `key_match` | **사양에 선언된** 조성(`key.tonic`, `key.mode`)과 라벨 | 라벨이 있는 필드(tonic, mode)가 모두 일치. tonic 은 이명동음 동일 처리 | tonic·mode 둘 다 없음 | 생성된 음을 분석한 조성이 아니라 선언값이다(컴파일러가 선언 음계 안에서만 쓰는 구조의 효과). text2midi 의 '자동 추정'과 같은 조건이 아님 |
| 박자표 일치 `time_signature_match` | MIDI 첫 `time_signature` 메타와 라벨(`"4/4"`) | 문자열 동일 | 라벨 없음 | 박자 변화는 보지 않음 |
| 마디 수 일치 `bars_match` | 사양의 전체 마디 수(섹션 합)와 `expect.bars` | 동일 | 라벨 없음 | 반복·인트로 등 구조 해석은 하지 않음 |
| 길이 규칙 `bars_min` | bars 를 **명시하지 않은** 프롬프트의 마디 수 | ≥ 8마디 (합의안 Q3: 기본 12, 최소 8). 12 와 다르면 사유에 "(기본 12마디와 다름)"만 적고 판정은 8 기준 | bars 라벨이 있는 프롬프트(그쪽은 `bars_match`) | 초 단위 길이는 템포·박자에 따라 달라 이 지표에 넣지 않음 |
| 악기 포함 `instruments_included` | 라벨 악기가 사양 트랙의 악기(`drums` 는 드럼 트랙 존재)에 모두 들어 있나 | 라벨의 모든 항목이 존재 | 라벨 없음 | **사양 기준**이다. MIDI 프로그램 번호를 직접 읽지는 않음. 라벨에 없는 악기가 더 있어도 감점하지 않음 |
| MidiCheck 유효 `midicheck_valid` | 생성된 MIDI 에 `check_midi` 오류 0건 | 오류 0건 | 없음(항상 적용) | 구조 유효성이지 음악적 타당성이 아님 |
| 결정성 `deterministic` | 같은 입력·같은 공급자로 2회 생성한 MIDI 바이트 동일 | 동일 | 생성 실패(비교할 바이트 없음) | 같은 프로세스·같은 의존성 버전 안에서의 확인. 다른 해시 시드 프로세스는 `tests/test_compiler.py` 가 따로 본다 |

### 참고 열 (합격 판정 아님)
- `attempts`, `retries`(= 시도 − 1), `fallback_used`: 재시도·폴백 여부. 요약에는 그룹별 개수만 적는다. 기본은 폴백 **끔**이라 숫자가 선택한 공급자 단독의 성능이다(`--fallback` 으로 켬).
- `generated`, `error`, `bars`, `midi_sha8`, `provider_used`.

### 청취 필요 (점수화하지 않음)
- `mood_listen`, `musicality_listen` 열은 모든 행에 `청취 필요` 로 고정한다. **무드 부합과 음악성은 자동 점수를 만들지 않는다.** 청취 루브릭·평가자는 연구 1팀 몫이다.

## 3. 출력

`--out DIR`(기본 `out/evalkit`, `.gitignore` 대상)에 두 파일을 쓴다.
- `results.csv`: 프롬프트별 한 줄. 지표마다 `이름`, `이름_reason` 두 열.
- `summary.md`: 층(A/B/C) × 언어(ko/en) 그룹과 층별·언어별·전체 열, 지표별 `통과/분모 (비율) · na N`, 재시도·폴백·생성 실패 개수, 실패 목록, 읽는 법과 한계. **분모 규칙을 요약 안에 적는다.**
- **재현성**: 시각·실행 시간·경로를 넣지 않는다. 같은 코드·같은 세트·같은 공급자면 두 파일이 바이트 단위로 같다(시험이 확인).

## 4. 공급자
- `rule`: 규칙 공급자(prompt2midi 의 `RuleProvider`).
- `fake`: 모든 프롬프트에 같은 고정 사양(C major, 100 BPM, 4/4, 12마디, 피아노·베이스·드럼)을 돌려주는 시험용. 세트와 무관한 기준선이자 하네스 자체의 시험용이다.
- `llm`: 이 도구는 실행하지 않는다("미실행(키 없음)", 종료 코드 0). 키 등록 이후의 실제 호출은 별도 도구(`tools/live_eval.py` 계획)가 맡는다.

## 5. 확장 지점 (이번 버전에 없음)
- **Intent v1 (문장에서 뽑은 필드의 일치율, 연구 1팀 3-1)**: Intent 스키마가 아직 없어 넣지 않았다. 들어올 자리: `evalkit/metrics.py` 의 `METRICS` 에 새 `Metric` 을 추가하고, `Context` 에 추출된 intent 를 담을 필드를 더하면 된다. `expect` 라벨은 이미 같은 이름(tonic·mode·tempo_bpm·time_signature·bars·instruments)을 쓰므로 추출 일치율과 MIDI 속성 일치율을 **따로** 보고할 수 있다(합의안 4절 위험 1).
- 연구 1팀 26항목 중 '지금 가능' 항목: 번호 대응표를 받으면 이 표에 열을 추가한다.

## 6. 연구 1팀 확인 사항 (서명 대기)
1. 위 지표 이름·합격 판정(특히 템포 허용 ±0.5 BPM, 조성은 선언값 기준, `bars_min` 기준 8마디)에 동의하는가.
2. `expect` 라벨 필드 목록이 세트 정답 라벨과 맞는가(`instruments` 값은 사양의 17종 + `drums`).
3. 층 A/B/C 의 정의(하네스는 집계 단위로만 사용).
4. 서명: 연구 1팀 ______ (날짜 ______)

## 1. 측정 조건 (연구 1팀 기록)
- 모델: HuggingFace `amaai-lab/text2midi`(2026-11-10 내려받음), 코드 원본 AMAAI-Lab/Text2midi(MIT), 텍스트 인코더 `google/flan-t5-base`.
- **체크포인트 자체의 라이선스는 미확인**(연구 1팀도 원문으로 확인하지 못함). 따라서 상업 이용 가능 여부도 미확인.
- 작업대 CPU 12코어(CPU 모델명 미확인), 메모리 상한 1,638MB, 생성 설정 max_len 512 · seed 0 · 스레드 4.
- 프롬프트 10개는 무드 하나씩: calm, sad, happy, energetic, dark, relaxing, epic, romantic, playful, meditative (`prompts.json`).

## 3. prompt2midi와 비교할 때 쓰는 법
- 비교 가능한 지표: 프롬프트당 지연, 메모리, 곡 길이, **유효 MIDI 비율**, 조성·템포 일치율(명시한 값이 있는 프롬프트만).
- text2midi가 템포를 못 따르는 한계(위 9/10)는 우리 설계의 근거 중 하나다: 템포·조성을 사양에서 명시하고 컴파일러가 보장하는 구조는 이 지표에서 우위를 가질 수 있다 [설계 판단, 실측 아님].
- 우리 쪽 비교는 같은 10개 프롬프트로 하되, LLM 호출이 필요한 부분은 키·비용 상한 확인 후에만 한다. 규칙 폴백(RuleProvider)은 키 없이 비교 가능.
- 주의: 연구 1팀 측정은 CPU 12코어·메모리 상한 환경이고 10개 표본이다. 일반화하지 않는다.

- 안소율 확인: HF 모델 카드 예시는 max_len=2000이고 연구 1팀 측정은 max_len=512다. 비교할 때 조건을 함께 적는다. 체크포인트 라이선스는 HF 모델 카드(2026-11-10 열람)에 항목이 없어 미확인 그대로.

## 4. 미확인
CPU 모델명, 체크포인트 라이선스, 무드 부합도, 청취 품질, max_len 512가 곡 길이를 제한하는 원인인지.
